🧠 How routing works
1. Your columns are matched to ours. By name where it is obvious, by meaning where it is not (msisdn, consignee, appt_dt), and by reading the values themselves when the header says nothing at all. What we settled on is shown above the results, so you can check it.
2. Each row is matched to a call. Every use case switched on for this agent declares the details it needs; the one whose needs your row actually meets is the one it gets. A use_case column, if you have one, overrides that.
3. Gaps are handled, not invented. What can be worked out is (days overdue from a due date); what cannot is left unsaid. A figure or a date is never made up to fill a hole. If something essential is missing, the row is held back and the missing column is named, and if nothing on the row matches any call this agent makes, it says so rather than falling back to a sales pitch.
